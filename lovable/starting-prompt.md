# Starting prompt

Status: drafted, not yet sent to Lovable. Test it with two different worlds before any child uses it.

## Before the prompt: the idea card (2 minutes, no laptop)

Each partner fills at least one line. Say it, write it or sketch it.

| | Your idea |
|---|---|
| My world: one place with one strange detail | |
| My clue: where the secret code is hidden | |
| My code: 3 numbers or one word | |
| My ending: what happens when someone escapes | |

Questions the facilitator can ask, one at a time and only if a pair is stuck:

- "Who will play it? What would make them smile?"
- "What is one thing in your room that could hide a number?"
- "Name two places the clue could be. Which is fairer for a first-time player?"

## The prompt children copy

Partner A copies everything in the box, fills the four blanks from the idea card, and sends it.

```text
Build a small escape room game on one screen, for 12-year-olds to play on a laptop.

MY WORLD: ______
MY CLUE: ______
MY CODE: ______
MY ENDING: ______

How it works:
1. One room with 4 to 6 things to click. Every click shows a short message or a close-up.
2. One of those things holds my clue. A careful player can work out the code from it.
3. One locked exit with a code box and an Open button.
4. A wrong or empty code keeps the exit shut and shows a short, funny message that fits my world. Never show the code.
5. A Hint button that tells the player where to look, but not the code.
6. The right code shows my ending.
7. A Restart button that puts everything back to the start.

Keep it simple:
- Use shapes, colours and emoji for the art. Big text and big buttons.
- No sign-in, no database, no saving, no sounds, no pictures from the internet, no AI inside the game.
- No timer or score unless I ask for one.
- A first-time player should escape in about one minute.
```

While Lovable builds, each child writes one prediction: "When I type the wrong code, I think the game will ______."

## Short version (if children must type the prompt)

Use only if copying from a shared document doesn't work on the student route.

```text
Escape room game on one screen. World: ______. Clue: ______. Code: ______. Ending: ______.
Things to click. Locked exit with code box. Wrong or empty code stays shut, never shows the code. Hint button points to the clue. Restart button. Emoji art. No sign-in, saving or internet pictures.
```

## Why each line is there

| Line | Reason |
|---|---|
| Four blanks only | The child's idea goes in before any AI suggestion; no spec form before play |
| "for 12-year-olds" | Keeps content and reading level suitable |
| 4 to 6 things to click | A room to explore, not one button; still finishable in a minute |
| Wrong or empty code, never show the code | The fairness rule children test later (right, wrong, empty) |
| Hint points to the clue | Sets up the teaching moment: should a hint reveal or guide? |
| Restart | Required; also the side-effect test after every change |
| No sign-in, database, saving, internet pictures, AI | Out of scope for the class; Lovable tends to add these unasked |
| No timer or score | Leaves those as choices children can add in Version 2 |

## What playtester must test for this prompt

Full path on two worlds: every object click, clue visible, wrong code, empty code, Hint, right code, ending, Restart, play again. Also check that Lovable added nothing from the "No" list.
